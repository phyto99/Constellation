Core Question

What does this multiplier configuration reward? Design topology to make that regime viable.

Design Guidelines

High M.count → dense clusters of short lines. Territory dominates. Star count matters most.
High M.dist → long corridors, sparse networks. Path length is the scoring engine.
High M.hq → HQ placement becomes the first strategic decision. Position near long-range lines.
High M.dest → Black holes are primary weapons. Map must make them reachable but dangerous.
Negative multipliers → that component becomes a penalty. Negative M.dist punishes long lines.

Failure Modes

Designing topology for M.count=500 then asking the AI to generate long-distance play. The map and the regime must match.
Setting all multipliers equal. Results in no dominant strategy, which usually means no interesting strategy.

Core Question

Does every team start with equivalent access — not mirrored layout, but equivalent strategic options?

Symmetry Types

Bilateral (2 teams) — reflected across a center axis. Simple, reliable, fair by construction.
Rotational 180° (2 teams) — same start zone rotated. More varied than bilateral, still provably fair.
Triangular 120° (3 teams) — no team has shorter path to wormhole or larger starting zone.
Asymmetric — valid only if equivalence is proven by equivalent star counts, line counts, and wormhole distance in each starting zone.

What Must Be Equivalent

Star count in expansion range±5%
Lines in starting zone±10%
Distance to nearest wormhole±15%
Cluster coveragesame count
Black hole reachabilitysame count reachable

Failure Modes

One team starts adjacent to a wormhole. Even if the map looks symmetric, if one path to the wormhole is shorter, one team has a structural advantage.

Core Question

Is the wormhole placed where both teams must fight to reach it? Are there at least 3 distinct path routes from each team's territory?

Placement Rules

Neutral contested space — not inside any team's natural expansion zone. If a team can reach it in round 1 unopposed, it's too close.
Three distinct paths minimum from each team. If all paths go through the same star, that star becomes a mandatory choke and removes strategic choice.
minReq timing — with default play speed (10 moves/round, 15 steals), minReq=2 is reachable in ~3 rounds. minReq=4 requires ~6 rounds. Design accordingly.
Multiple wormholes create a 3-way tension: race your wormhole, block theirs, or ignore both and win on score.

Format

[x, y, 3, minReq, maxReq]
e.g. [160, 90, 3, 2, 4] — wormhole at center, req randomized 2–4

Failure Modes

Wormhole placed at map edge. Only one team can approach without crossing the other's territory. This is not a win condition — it's a free win.
Single path to wormhole. The map collapses into one decisive choke point. Every game plays identically.
minReq too high. Game never ends via wormhole — always score-based. Wormhole becomes meaningless.

Core Question

Are clusters placed where holding them creates meaningful control — not scattered, not concentrated?

Placement Archetypes

Near wormholes → protected launch pads. Hard to steal, so teams must path around them. High-value, highly contested.
Map center → contested anchor. Whoever holds it gains stability across the middle. Creates a clear strategic objective.
Starting zones → protected home bases. Reduces early-game chaos. Teams have a stable foundation to build from.
Corridor chokepoints → whoever holds the cluster controls the corridor. Powerful but potentially game-warping if there's only one corridor.

Format

[x, y, 2]
No minReq/maxReq. Protection activates automatically when connected stars are owned by the cluster's team.

Calibration

0 clustersConstant steal chaos. High variance.
1–2 clustersMinimal stability. Mostly volatile.
2–4 clustersOptimal. Clear anchors without stalemate.
5+ clustersStalemate risk. Territory locks early.
Clustering all clusters in one region. One team gets a fortress, the other gets nothing. The map is decided by who wins the cluster area.

Core Question

Is each black hole reachable by multiple teams, placed in contested territory, with a req range appropriate to how often you want it triggered?

Requirement Calibration

req 2–3 → active trap. Triggered frequently. Changes board state every few rounds. High chaos.
req 3–4 → balanced. Meaningful threat. Triggered by a committed team. Creates a clear tactical decision.
req 4–5 → background threat. Rarely triggered. Mostly shapes movement patterns by making certain star chains dangerous.

Format

[x, y, 4, minReq, maxReq]
e.g. [80, 45, 4, 2, 4] — black hole at (80,45), req randomized 2–4

Failure Modes

Black hole only reachable by one team. It's not a mutual threat — it's a free weapon for that team. Remove or relocate.
Black hole placed in isolated region with no valuable connected stars. Triggering it destroys worthless territory. No strategic depth.
Too many black holes. The map becomes a minefield. Players spend most moves avoiding explosions rather than building networks.

Core Question

Is every star reachable from every other star? Does line density vary purposefully — dense in contested zones, sparse at edges?

Connectivity Patterns

Hub star (6–12 lines) — high-value choke point. Contested. Losing it cuts multiple paths simultaneously.
Corridor (2 lines each in chain) — contested pathway between regions. Each star on the chain is worth controlling.
Dense web (4–6 lines each) — many routing options. Hard to blockade. Rewards global thinking over local tactics.
Leaf star (1 line) — high-risk exposed position. Easy to steal. High reward if maintained.

Metrics

Failure Modes

Uniform density across the entire map. No gradient from center to edge. All positions feel equivalent. No flow toward or away from contested zones.
Average degree < 2. Stars become isolated quickly after any steals. Network collapses too easily.

Core Question

Are all applicable strategies viable simultaneously? Is the optimal choice non-obvious until well into the game?

Strategy Checklist

A. Rush — is there a path to the wormhole that a committed team can reach before the opponent blocks it? If yes, viable.
B. Territory — can a team win on count score alone by expanding aggressively? If yes, viable.
C. Network — do long-distance lines exist that make distance scoring competitive with territory scoring? If yes, viable.
D. Disruption — can black holes be triggered to meaningfully damage the opponent's score at a reasonable cost? If yes, viable.
E. Defense — can a team hold 2–3 clusters, build stable territory, and win without ever racing the wormhole? If yes, viable.

The Optimal Choice Test

A great map passes this test: after round 2, no player should be certain which strategy will win. If the answer is obvious from turn 1, the map has a dominant strategy and is less interesting.

Black holes cannot be claimed or owned. They exist only as triggers. All scoring from them flows through M.destruction × destroyed_star_score.

Star Types

JSONNameMechanic
1 Normal Standard node. Claimable and stealable.
2 Cluster Cannot be stolen. All directly connected stars become unsteallable while connected.
3 Wormhole Win condition. First team to form [minReq–maxReq] non-overlapping paths through it wins immediately. Paths may not share any star.
4 Black Hole Explosive. When a team forms [minReq–maxReq] paths to it, all of that team's stars connected to it are permanently destroyed. Cannot be claimed.

minReq / maxReq are optional positions 3 and 4 in the star array. Game randomises actual requirement within that range at start. Default: 3. Maps do not need to include all types.

Scoring Formula

finalScore =
  lineCount    × M.count
+ lineDistance × M.dist
+ hqDistance   × M.hq
+ destroyed    × M.dest
ComponentMeasuresDefault ×
lineCountLines with both endpoints owned by team500
lineDistanceEuclidean length sum of owned lines1
hqDistanceLength sum of lines connected to HQ stars10
destroyedScore from black hole explosions1
All multipliers can be any real number including negative. Negative values turn that component into a penalty.
