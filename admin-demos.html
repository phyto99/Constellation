Admin panel — mobile support approaches

1. @media queries only
At a breakpoint, sidebar goes full-width and stacks above content. No JS. Pure CSS. Everything is still there — just reflowed. Resize the desktop frame to see it collapse.
desktop
mobile (same file, narrow viewport)
Tradeoff: all the desktop complexity is still in the DOM — long config panels just scroll vertically.
2. Hamburger drawer
Sidebar becomes a fixed overlay. A button slides it in/out. Main content is always full width. Click the ☰ button in the mobile frame.
desktop (sidebar always visible)
mobile — sidebar is a drawer (click ☰)
Tradeoff: slightly more JS (~15 lines). Sidebar content still needs to be scrollable. Overlay/escape to close is expected UX.
3. Touch targets (pointer: coarse)
No structural change. On touch devices, interactive elements get 44px minimum height. Uses @media (pointer: coarse) which targets touchscreens specifically, not screen width.
mouse device — tight targets
touch device — 44px targets
Tradeoff: purely additive, zero risk. Doesn't fix layout overflow — only improves tap accuracy. Should be combined with another approach.
4. Separate simplified mobile page
Two different pages: full admin for desktop, a stripped version for phones that only shows the 3 most common mobile tasks — share a join link, check who's in, and start/stop. Redirect on load based on screen width.
desktop — full admin
mobile — simplified page (/admin-mobile)
Tradeoff: double the maintenance surface. But mobile admin UX is genuinely different from desktop — config belongs on desktop, link-sharing and start/stop belong on mobile.
5. Container queries
Individual panels respond to their own width rather than the viewport. A wide panel shows fields inline; a narrow panel stacks them. Useful when panels vary in size regardless of screen width.
wide container — inline fields
narrow container — same component, stacked
Tradeoff: container queries are component-scoped — they don't solve the sidebar/layout problem, only the field layout within panels. Best used alongside approach 1 or 2.
