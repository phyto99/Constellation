The Single Unifying Principle

The diagnosis. The current system has five separate optimization objectives — mode coverage, difficulty targeting, template selection, spectrum zone, overlay timing — each designed independently and bolted together. That is not a system. That is a checklist with arrows. A beautiful system has one principle that everything else falls out of.
The Single Objective
next_session = argmaxS 𝔼[ KL( posterior_student ‖ prior_student ) | session S ] subject to: S is within the student's zone of proximal development
Every session is an experiment. The student has a prior cognitive model — beliefs about which strategies work under which conditions. The session is a perturbation. The system's only job: choose the perturbation that produces the maximum update to that model. This is expected information gain. Everything else is derived from it.

The mutual modeling insight

The student is modeling the system — building beliefs about what each mode rewards, how to read the loading terminal, when INVERSION is active. The system is modeling the student — tracking mode Elo, behavioral signals, heuristic use.

Each session, both models update. The student's posterior is more precise than their prior. The system's uncertainty about the student decreases. The next session is chosen from a more informed position, by a student with a more capable model.

The convergence target is not "student wins consistently." It is: student's cognitive model reaches maximum complexity across all six dimensions. At that point the system has nothing left to teach. The student generates maximum entropy outputs — unpredictable, creative, adaptive play. That is the objective.

The critical distinction. Current system: parameters are asserted from first principles and educational science heuristics. They are probably mostly correct — the science is solid. But "probably correct" is different from "verified correct for this student population playing this game." Derived system: the same decisions, but each parameter has a clear measurement criterion. You know what data would confirm or refute each value. That is what makes a system scientific rather than well-designed.

Why the Curve is Asymmetric

The information gain curve peaks at the lower edge of the flow zone (~30–40th predicted percentile) and drops asymmetrically:
RegionWhat happensWhy gain is low
Below ZPD Student overwhelmed Cannot process the signal. Posterior ≈ prior from confusion, not certainty.
ZPD entry Hard but tractable Maximum surprise + maximum ability to update. Steep gain increase.
Flow zone lower edge Barely winning Peak information gain. Surprise is high, strategy can be updated, outcome is interpretable.
Flow zone upper edge Comfortable win Outcome expected. Small posterior update. Gain decays slowly.
Above flow Bored No surprise. Student already knows the answer. Gain approaches zero slowly.
Overwhelm kills signal faster than boredom. This asymmetry means the system should err toward slightly-too-easy rather than slightly-too-hard — the information gain loss from over-challenge is steeper than from under-challenge. The 0.85 coefficient encodes this asymmetry.

Per-Mode Information Landscapes

Each mode has a different information gain profile because each targets a different cognitive skill with different variance properties. INVERSION has the widest ZPD (the skill is tolerance of uncertainty — hard to be overwhelmed by uncertainty if that's the target). WORMHOLE has the narrowest (binary outcome: activation or not — little partial information available).

The ZPD as the Valid Region

ZPD(student, mode) = [diff_min, diff_max] diff_min = point where E[KL] > noise_floor ≈ elo[mode]/999 − 0.25 (hard lower bound) diff_max = point where student can still form interpretable posterior ≈ elo[mode]/999 + 0.15 (hard upper bound) system_target = diff_min + 0.3 × (diff_max − diff_min) ≈ elo[mode]/999 × 0.85 → lower third of ZPD → 30–40th predicted percentile
The ZPD is not a fixed range — it is student-specific and mode-specific. A student with Elo 200 in SPATIAL has a different ZPD than a student with Elo 700. The system targets the lower third of the ZPD, not the center, because information gain peaks there — the student is at their ceiling, maximally surprised, maximally updating.

The ZPD also widens as the student advances. A more capable student can absorb larger perturbations without the signal becoming noise. This means the difficulty curve steepens with competence — harder challenges become available faster as Elo improves.

The Mutual Information Loop — Architecture of a Living System

A pipeline processes. A loop learns. The distinction is that in a loop, the output of each cycle changes the input of the next. Both the student and the system are modeling each other. Both update after every session. The system that exists after session 50 is not the same system that ran session 1 — it has a richer model of the student. The student who plays session 50 is not the same student who played session 1 — they have a richer cognitive model. This mutual refinement is the mechanism of development.

Student model update

Before session: student has prior beliefs about what each mode rewards, which strategies work, how the system behaves.

After session: behavioral signals (score, rank, steal_rate, hq_connection_speed...) update the prior. The posterior is more accurate.

Rate of update = information gain of the session. Optimal sessions produce maximum posterior update.

The session as mediator

The session is the information channel between student and system. It is chosen by the system to maximize mutual information — to be maximally informative to both parties simultaneously.

The system learns from the session. The student learns from the session. Neither party is passive. The session is not a test — it is a joint experiment.

System model update

Before session: system has prior beliefs about student's mode Elo, bot affinity, behavioral signals, current ZPD.

After session: outcome and signals update the prior. System's uncertainty about the student decreases. The entropy budget is this uncertainty, decreasing over time.

At budget 5 (50+ sessions): system has low uncertainty → precise interventions. At budget 1: high uncertainty → coarse-grained decisions only.

Maximum entropy as the final state

The student who has completed convergence is not predictable. They do not have a "strategy" — they have a model of the game sophisticated enough to generate the appropriate strategy for any configuration on the fly.

This is maximum entropy output: the observer cannot predict their behavior from prior sessions, because their behavior is fully conditioned on the current configuration, not on habit.

This is cognitive flexibility at full expression. The goal of INVERSION mode — originally conceived as an overlay — becomes the student's permanent operating state. Every session is effectively INVERSION, because the student is always reasoning from first principles rather than pattern-matching.

Evolution Path — From Well-Designed to Proven

The epistemological gap. The current system applies solid educational science — Vygotsky ZPD, Csikszentmihalyi flow, Bjork's desirable difficulties, spaced repetition, interleaving. These validate the architecture. They do not validate the specific parameters. The 0.85 coefficient, the 6-session window, the 30–40th percentile target, the P=0.25 overlay probability — these were derived from theory. Theory says the right direction. Only data says the right magnitude.

The Four Phases

Phase 1 — Tune (now)
Add Elo velocityTrack ΔElo over last 5 sessions. Student improving fast → stay in mode longer. Student plateauing → push mode change even if last outcome was good.
Forgetting decayReduce difficulty on mode return after long gap. Decay = exp(−days / half_life). Initial half_life ≈ 14 days.

Phase 2 — Instrument
Track objective functionLog ΔElo per session as primary metric. This is the thing being maximized. Currently it is computed but not tracked as the driving signal.

Retention trackingAfter N sessions away from a mode, how much Elo was retained? This calibrates the forgetting decay half_life.

Replace hardcoded params0.85 coefficient, zone thresholds, overlay probabilities → learned from Phase 2 data. The empirically optimal value replaces the theoretically derived value.
Student-specific curvesThe information gain curve shape may differ by student. Some students have wider ZPDs than others. The system should learn this per student.
Phase 4 — Validate
External validityDo in-game mode Elo gains correlate with performance on external cognitive tasks? This is the fundamental question the system cannot answer internally.
Controlled comparisonAdaptive system vs random session assignment. If the adaptive system doesn't outperform random assignment in a controlled comparison, the complexity isn't justified by outcomes.

What "objectively perfect" actually requires

A validated objective function

Currently: maximize rate of mode Elo improvement.
But: is Elo the right proxy? Options are mode Elo gain, cross-mode transfer, long-term retention, external cognitive task performance, student engagement and return rate.

These are not the same objective. The system that maximizes short-term Elo gain may not maximize long-term retention. Choosing the objective is a values decision, not a technical one.

A feedback loop that tunes the system

Currently: system emits SessionSpec and receives {rank, percentile, signals}. It does not use those signals to update its own parameters.

Required: after N sessions, parameters that produced high ΔElo should increase in weight. Parameters that produced low ΔElo should decrease. The system should be tuning itself from its own outcomes — not waiting for a human to read the logs.

Controlled comparison evidence

Currently: the system is well-designed by first principles. It implements what educational science says should work.

Required: evidence that it actually works better than simpler alternatives. A random session generator might produce similar Elo gains with far less complexity. Until a controlled comparison exists, "objectively perfect" is an aspiration, not a claim.
