The Selection Criterion — What Belongs in a Perfect System

THE META-PRINCIPLE
Include variable V ⟺ I( session_accuracy ; V | existing_variables ) > ε
A variable belongs if and only if it provides information about session selection accuracy that is NOT already contained in the variables already present. This is mutual information used as a feature selection criterion. It is not a philosophical preference. It is a measurement.

Why this criterion is the right one

The system's objective is maximum student development. Every decision it makes — which mode, which template, which difficulty — is an attempt to select the session that produces the largest update to the student's cognitive model.

A variable is useful only insofar as it helps the system make that selection more accurately. A variable that does not improve selection accuracy is not merely redundant — it actively harms the system by adding noise to the decision process, increasing the complexity of maintenance, and reducing the interpretability of outcomes.

The criterion is self-applying. You use it to decide which student variables to track. You use it to decide which system parameters to keep. You use it to decide which game signals to capture. The same question at every level: does this improve the accuracy of what comes next?

What "should some variables be left out?" resolves to

Yes. Several variables in the current system fail the criterion:

And several variables are missing that would clearly pass the criterion:

The philosophical point on parsimony. The perfect system is not the most comprehensive system. It is the system with minimum description length: the smallest set of variables that is sufficient to select the optimal next session. Every variable beyond that minimum is not neutral — it adds noise, complexity, and maintenance cost. Parsimony is not a trade-off against accuracy. Below the sufficiency threshold, removing variables hurts accuracy. Above it, adding variables hurts it. The minimum sufficient set is the exact correct set.

Minimum Sufficient Specification — The Three-Layer Architecture

Three layers, cleanly separated. The state layer describes where the student is. The selection layer decides where they should go next. The implementation layer makes it happen in the game. The layers are independent in the right way: you can replace the game without changing how you think about the student, and you can improve how you think about the student without changing how you select sessions.

Layer 1 — STATE

S(student, t) = { mode_elo[6], ← position mode_elo_velocity[6], ← momentum sessions_since_last[6]← recency }

A point in an 18-dimensional space. Everything the system needs to know about where the student is, how fast they are moving, and how long they have been away. Nothing else. The state is minimal and complete.

What mode_elo alone cannot tell you. Two students with identical mode_elo[6] may have completely different needs: one is improving rapidly (high velocity) and needs to stay in the current challenge arc; the other has plateaued (zero velocity) and needs a fundamentally different perturbation. Without velocity, the system treats them identically. That is wrong.

Layer 2 — SELECTION

next(S) = argmaxC 𝔼[ KL( posterior_S | config C ) ] subject to: C ∈ ZPD(S) C.mode ∈ hypercube(S) C.template ∉ recent(S)

One operation on the state. The system asks: given where the student is now, which configuration of the game produces the largest expected update to their cognitive model? Subject to three hard constraints: stay within what the student can handle (ZPD), guarantee breadth across modes (hypercube), and don't repeat recent templates.

Everything else — the spectrum zone, the difficulty coefficient, the overlay probability — is an implementation of this argmax in terms the game can act on.

Layer 3 — IMPLEMENTATION

config(argmax_result) = { mode, template, ← max locked axes difficulty, ← elo_vel × 0.85 spectrum_zone, ← exposure depth overlay_flags, ← if eligible codename, loading_sequence }

The translation of an abstract selection into concrete game parameters. This layer is game-specific — it knows about Constellation's templates, multipliers, bot types. If the game changes, only this layer changes. The state representation and the selection principle are game-agnostic.

The loading sequence and codename are in this layer, not the selection layer. They are the psychological implementation of the session — they affect engagement and therefore signal quality, but they do not change what the system has decided to train.

Why 18 dimensions and not more

Dimension groupWhat it capturesCannot be derived from others
mode_elo[6]Current cognitive position per dimensionYes — no other variable tells you where the student IS
mode_elo_velocity[6]Rate of change per dimensionYes — elo alone doesn't distinguish improving vs plateaued at same value
sessions_since_last[6]Forgetting decay input per dimensionYes — total session count doesn't tell you which modes have been neglected
Why not add more? Each additional dimension increases the state space exponentially. At 18 dimensions the system already requires many sessions to estimate the state reliably. Adding brain_metrics (8 more), bot_affinity (6 more), or behavioral signal history (unbounded) expands the state space faster than the data can fill it. The result is a system that is wrong with great precision — it makes highly specific selections based on an unreliable state estimate.
The recency dimension specifically. Sessions_since_last is not a proxy for forgetting — it IS the forgetting input, directly. The forgetting curve (Ebbinghaus) is well-validated: retention decays approximately exponentially with time. Difficulty on mode return should scale as: d_adjusted = d_base × exp(−days/half_life). The half_life is the one parameter to learn from data (~14 days initially). Without this dimension, a student returning to SPATIAL after a month receives the same difficulty as one who played it yesterday. That is a systematic error.

Self-Similarity — The System Applies Its Own Principles to Itself

The recursive structure

The system selects sessions to maximize the student's information gain. It uses mutual information to decide which student variables to track. It uses the same criterion to decide which of its own parameters to keep. It applies the information-maximization principle at every level of its own design. A system that uses the same principle at every scale is structurally beautiful. A system that uses different principles at different levels is not — it is a collection of solutions that happen to be assembled together.

Scale 1: Session selection

Which session maximizes the student's information gain?

argmax_C 𝔼[ KL(posterior_S | C) ]

The fundamental operation. Applied to choose the next session from all possible game configurations.

Scale 2: Variable selection

Which variables improve session selection accuracy?

include V ⟺ I(accuracy; V | existing) > ε

The same logic applied to the system's own representation. A variable is included if it reduces the system's uncertainty about which session to select next.

Scale 3: Parameter tuning

Which parameter values maximize developmental outcomes?

θ* = argmax_θ 𝔼[ ΔElo_velocity | θ ]

The same logic applied to the system's own parameters. The 0.85 coefficient, the 6-session window, the overlay probability — each is an argument to the same optimization.

The anti-pattern — where current systems break self-similarity

DecisionCurrent justificationWhat self-similarity requires
Difficulty coefficient 0.85 Derived from Vygotsky ZPD theory — targets lower edge of flow zone Should be the value θ that maximizes observed ΔElo_velocity across students. Theory suggested the direction; data should determine the magnitude. Currently asserted, not measured.
Overlay probability P=0.25 Seems right for a 1-in-4 surprise rate given eligibility Should be the probability that maximizes reversal_learning_speed signal quality in eligible students. A purely intuitive choice that should be replaced by the value that actually produces fastest cognitive flexibility development.
Latin hypercube window = 6 There are 6 modes — one window covers all modes once The window size should minimize the expected time for a student to develop all 6 modes above a threshold. For some students 6 may be too small (mode mastery requires more repetition); for others too large (coverage forces modes they're already strong in). Should be student-adaptive.
Entropy budget thresholds (0, 1, 6, 20, 50) Reasonable session counts for reliable inference at each level Should be derived from the actual information gain curves of the system's own inference. At how many sessions does global Elo inference become reliable? Measure the inflection point. Don't guess.
Forgetting half_life ≈ 14 days Consistent with general Ebbinghaus curve literature Should be measured on this specific student population for this specific game. Cognitive skill retention in competitive games may have a different curve than the original verbal memory experiments. The general direction is right; the magnitude must be learned.
None of these are failures of design — they are the correct starting values given no data. The system that runs on day one must use theory-derived parameters because there is no data yet. The self-similar system records the data it needs to eventually replace every asserted value with a measured one. The transition from Phase 1 (asserted) to Phase 3 (learned) is not a redesign — it is the same system becoming more accurate about itself. A self-similar system knows how to improve itself. That is what makes it complete.

The Formal System — Complete Minimal Specification

This is the complete specification. It is minimal — nothing can be removed without losing something necessary. It is sufficient — nothing need be added to achieve the objective. Every parameter marked [ASSERTED] should eventually become [LEARNED] from observed ΔElo_velocity data. Every threshold marked [MEASURE] is a claim that should be tested.

The State

S(student) = { e[6] : mode_elo[6] ∈ [0,999]⁶ ė[6] : mode_elo_velocity[6] ∈ ℝ⁶ (Δelo/session, signed) τ[6] : sessions_since_last[6] ∈ ℝ⁺⁶ (days) o : last_outcome = (percentile, margin) h[6] : recent_template_ids[6] ∈ list (last 3 per mode) } Derived (compute, do not store): global_elo = weighted_mean(e[6]) ← NOT independent streak = run_length(session_history) ← NOT independent budget = f(min sessions per mode) ← NOT independent

The Objective

maximize over student lifetime: Σ_t 𝔼[ KL( S(t+1) ‖ S(t) ) ] where KL is over the 6-dimensional cognitive position space. This is the cumulative cognitive displacement — how far the student has moved from their starting position across all 6 dimensions by session T. Note: KL here is a proxy for development. The true objective is external cognitive transfer, which requires Phase 4 validation to confirm.

The Selection Function

select(S) = argmaxC ∈ valid(S) 𝔼[ΔKL(C, S)] valid(S) requires all of: C.difficulty ∈ ZPD(S) ZPD_min = e[mode]/999 − 0.25 [MEASURE] ZPD_max = e[mode]/999 + 0.15 [MEASURE] target = ZPD_min + 0.3×width [ASSERTED → 0.85×e/999] C.mode ∈ hypercube_eligible(S) window = 6 sessions [ASSERTED → MEASURE] weight = (e[mode]/999)^0.7 × 1/(sessions_seen+1) × elo_velocity_bonus(ė) [NEW] C.template satisfies: C.template.id ∉ h[mode] prefer max(locked_axes_count) C.difficulty adjusted for recency: d_adj = d × exp(−τ[mode]/λ) [λ ≈ 14 days, ASSERTED → MEASURE] C.overlay_flags: P(INV) = 0.25 if e[mode]<300 AND τ[mode]<7 AND sessions≥6 [ASSERTED] P(INV) = 0.05 otherwise cooldown: ≥3 sessions between INV on same mode [NEW]

The completeness claim — and its limits

This specification is complete within the competitive development objective. Given the goal of maximizing mode Elo development across 6 cognitive dimensions, this is the minimum sufficient specification — nothing can be removed without losing something necessary, nothing need be added to achieve the goal.

It is not complete in two ways that matter:

1. The objective may be wrong. Mode Elo development is a proxy for cognitive development. It may not be the right proxy. External cognitive transfer (do SPATIAL gains improve real-world spatial reasoning?) has not been measured. The system is perfectly optimized for the wrong objective until Phase 4 validates the proxy.

2. The parameters are asserted, not learned. Every value marked [ASSERTED] is a theory-derived starting point. The system as specified above knows how to replace each of them with learned values — the measurement criteria are explicit. Until the measurements are taken, the system is well-designed but not empirically validated.

Philosophical beauty does not require empirical validation. Objective perfection does. The system is philosophically complete. It will become objectively perfect when the asserted values become learned ones.
