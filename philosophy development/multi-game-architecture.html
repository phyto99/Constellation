The One Principle
argmax E[KL(posterior ‖ prior)]
Maximize expected information gain about the student's cognitive model per session.
This principle is game-agnostic. The posterior is over cognitive state, not game state. Any game that moves the posterior is valid. The question is always: which game, which configuration, tells us the most we do not yet know?
§ 1
The Generalization Problem

The current system is optimized for Constellation. The compiler maps a student's six-mode Elo vector onto a twelve-parameter game config and produces a session with maximum expected information gain. This works because the game's mechanics — star counts, multipliers, HQ placement — are legible cognitive levers. Adjusting count_mult isolates the QTY dimension. Adjusting hq_mult isolates HQ reasoning. The config space and the cognitive space are roughly co-extensive.

When a second game enters the system, this alignment breaks. GOLAD has no star counts. Geobridge has no multipliers. C4D has no rounds in the Constellation sense. Each game is a different projection of cognitive space onto mechanical parameters. The compiler cannot naively apply Constellation's model to any other game.

The generalization problem is: given a student's cognitive posterior derived from any combination of games, select the game and configuration that maximizes expected information gain across the entire suite.

This requires three things the current system does not have:

1. A universal cognitive space — a set of dimensions that are meaningful across all games, such that each game can be expressed as a probe of some subset of those dimensions.

2. A two-level compiler — a game selection step (which game maximizes E[KL] given the current posterior?) followed by the existing config selection step (which settings within that game maximize E[KL]?).

3. A cross-game transfer model — evidence that performance in Geobridge on dimension X predicts performance in C4D on dimension X, i.e., that the dimensions are genuinely cross-game rather than game-specific skills.

This document specifies the architecture for all three. The cognitive dimension mappings are ASSERTED — they are the most plausible prior given the game mechanics, but they cannot be verified until multi-game Ledger data accumulates and a factor model is fitted. The architecture is CANONICAL — it is the correct structure regardless of which specific dimensions are confirmed.

§ 2
The 8 Cognitive Dimensions ASSERTED

These dimensions are derived from the union of all cognitive demands observable across the four games. They are not arbitrary — each is isolable by specific config parameters in at least one game. The labels and boundaries will be revised by empirical factor analysis once sufficient multi-game data exists. Until then, treat these as the best-available prior over the latent space.

SIM
Simulation / Forward Prediction
Can the student project future state from current state under a known rule system? This is not memory — it is dynamic rule application. The student must hold the rule system in working memory and apply it iteratively to a changing state space.
Probe: GOLAD (CA evolution prediction); C4D (adjacency chain completion); Constellation (move sequence projection)
GOLAD C4D Constellation Geobridge
COM
Strategic Commitment
Can the student commit to a plan and execute it consistently under pressure? Commitment requires forming a strategy, betting on it, and not abandoning it at the first setback. The gap between intended and executed strategy is directly measurable.
Probe: Geobridge (bid → must execute contract); C4D (permanent ownership — every claim is irreversible); Constellation (HQ placement round, archetype_tag consistency)
Geobridge C4D Constellation GOLAD
OPP
Opponent Modeling
Can the student form and update a model of what opponents will do? This is not the same as winning — a student can have excellent opponent models and still lose. The diagnostic is whether the student's actions reflect accurate prediction of opponent behavior.
Probe: Geobridge (bidding inference, alliance decision); GOLAD (interference placement); Constellation (steal timing, bot aggression response)
Geobridge GOLAD Constellation C4D
TOP
Abstract / Topological Reasoning
Can the student reason about structural relationships that have no intuitive visual form? In 2D games, adjacency is visible. In 4D polytopes, adjacency must be inferred from abstract rules. In cellular automata, non-local effects cascade through topological structure.
Probe: C4D (4D polytope adjacency — genuinely non-visual); GOLAD (CA non-local pattern effects); Constellation (map topology, wormhole structure)
C4D GOLAD Constellation Geobridge
ADP
Rule Induction / Adaptation
When the rules change, how quickly does the student update their mental model and modify behavior? This dimension requires the student to detect the change, identify which rules are now different, form a new hypothesis, and act on it. The speed and accuracy of this cycle is the signal.
Probe: GOLAD (birth/survive rule variants — variable by design); Constellation (INV mode / negative multipliers); C4D (wMode oscillation); Geobridge (eclipse region activation)
GOLAD Constellation C4D Geobridge
OPT
Resource / Quantity Optimization
Can the student maximize a scalar objective under constraints? This is the most "standard" cognitive task — closest to traditional IQ-style reasoning. But it matters: some students have high OPT and low everything else, which is a meaningful profile (not gifted; optimized for measurable tasks).
Probe: Constellation (QTY/MOVE modes — direct scalar optimization); C4D (scoring [1,3,9,27] — exponential maximization); Geobridge (hand selection optimization)
Constellation C4D Geobridge GOLAD
MOS
Multi-Objective Synthesis
Can the student simultaneously hold and balance multiple competing objectives without collapsing to a single strategy? This is the hardest of the scalar dimensions. Students with high MOS perform well in COMBO mode but do not simply average the sub-objectives — they actively trade off between them in real time.
Probe: Constellation (COMBO mode — explicit multi-objective); C4D (plane completion vs. cell count vs. fog inference — implicit multi-objective); Geobridge (bid + execute + opponent model running in parallel)
Constellation C4D Geobridge GOLAD
KNW
Declarative Knowledge Integration
The only content-dependent dimension. Some games require stored factual knowledge to perform well — not because knowledge IS the cognitive skill, but because integrating knowledge with strategy IS a cognitive act. The gap between what a student knows and what they deploy is itself a signal. This dimension does not exist in games where all needed information is on-screen.
Probe: Geobridge (geography facts — GDP, area, population, trade — integrated into bidding strategy); GOLAD (pattern library recall — gliders, still lifes, oscillators)
Geobridge GOLAD Constellation C4D
Refutation Conditions These 8 dimensions will be revised when: (1) factor analysis on multi-game Ledger data reveals a different latent structure; (2) two dimensions that are listed separately load onto a single factor at r > 0.85; (3) a dimension produces no cross-game predictive signal after 50 multi-game student profiles. The architecture survives revision of the dimensions — only the number and names change, not the principle.

On GOLAD's p1Type / p2Type (AI opponent). When p2Type = AI, GOLAD becomes a single-player experience against a deterministic opponent. This changes the OPP dimension loading: opponent modeling against a known algorithm is different from modeling a human. The AI opponent should be used to isolate SIM and ADP; human opponent to isolate OPP. The compiler must know which mode is active when interpreting the session signal.

On C4D's polytopePath. The polytope is the most powerful lever in the suite for TOP. A tesseract (4D hypercube) has 8 cells, 24 faces, 32 edges — adjacency is computationally but not visually derivable. Moving to a 16-cell or 120-cell polytope increases the demand non-linearly. polytopePath is effectively the TOP difficulty dial. No other game in the suite has a direct equivalent — this is C4D's unique contribution to the posterior.

On Geobridge's knowledge vs. skill ambiguity. A student who knows geography can bid confidently and win without exercising COM or OPP deeply. The diagnostic is not the outcome — it is the gap between knowledge level (assessable externally or via performance on fact-pure rounds) and strategic execution quality. Geobridge sessions are most informative when the student's geography knowledge baseline is approximately known.

Reading the matrix. Each column is a cognitive dimension. The game with the most ▪'s in that column is the one to select when the posterior has highest uncertainty in that dimension. GOLAD is the primary SIM and ADP instrument. Geobridge is the primary COM, OPP, and KNW instrument. C4D is the primary TOP instrument. Constellation covers OPT and MOS most completely — its advantage is that those dimensions are individually isolable via multipliers, which the other games cannot match.

Dimension monopolies. TOP (C4D) and KNW (Geobridge) are owned by a single game — no other game in the suite provides equivalent signal on those dimensions. This means the compiler cannot substitute. If the posterior has high uncertainty on TOP, C4D must be selected regardless of other considerations. These are structural game uniquenesses that cannot be overcome by configuration alone.

Coverage gaps. KNW loads only on Geobridge at the primary level. This is a deliberate feature: factual knowledge integration is a real cognitive process worth measuring, but it requires a specific game design to surface. Future games may add KNW probes in other domains (historical, scientific, linguistic). Until then, Geobridge is the sole KNW instrument and its signal on other dimensions should be interpreted with the KNW confound in mind.

Part II — Implementation Architecture
§ 5
The Two-Level Compiler

The current compiler operates within Constellation. It takes a student's cognitive state and produces a Constellation config vector. The multi-game compiler adds a preceding step: game selection. The result is a two-level decision process where the game is the outer variable and the config is the inner variable.

1
Posterior Readout
Read the current student model: eight-dimensional cognitive posterior with uncertainty estimates per dimension. Identify the two or three dimensions with highest remaining uncertainty (lowest sample count or widest confidence interval). These are the target dimensions for this session.
↓
2
Game Selection — argmax E[KL] at the game level
For each available game, estimate E[KL] if that game were selected. This is done by looking up the composition matrix (§4) and scoring each game against the target dimensions. The game whose primary dimensions overlap most with the target dimensions is selected. If the primary game has been played in the last 3 sessions (staleness guard), prefer the next-best alternative. Constraint: do not select a game the student finds terminally unengaging — engagement is a hard floor, not an optimization target.
↓
3
Config Selection — argmax E[KL] within the selected game
Given the selected game, find the config that maximizes E[KL] over the target dimensions. Each game has a set of cognitive levers (§3). The compiler sets those levers based on the student's current posterior on each relevant dimension: high uncertainty → high-difficulty setting on that lever; low uncertainty but active → maintain for calibration; below ZPD → reduce difficulty. For Constellation, this is the existing compiler. For other games, this is the same logic applied to their config spaces.
↓
4
Zone Assignment
Zone (REMATCH → RADICAL) still applies in the multi-game context, but the reference frame changes: zone describes the distance from the student's last session on the selected dimensions, not from the last session in the same game. A RADICAL assignment in the multi-game context means maximum distance in the target dimension space — potentially a different game entirely, not just a different config of the same game.
↓
5
Terminal Output
The terminal message the student sees now includes the game identity (if it changed from last session), the zone, and — at appropriate disclosure tiers — which dimensions are being probed. The student's awareness of the dimension system is itself part of the Alpha track: at singularity, they understand that GOLAD probes SIM and can request it by name.

Session variety and engagement. The two-level compiler naturally produces variety across sessions — not by randomizing, but by following the posterior. High uncertainty in undersampled dimensions means different games will be selected in sequence. When the posterior converges uniformly across all dimensions, the compiler will cycle games to maintain calibration and detect drift. Variety is an emergent property of information-seeking, not a designed feature.

What the compiler does not do. It does not select games to balance game time across titles. It does not avoid a game because the student is performing poorly in it (poor performance is high information). It does not optimize for student preference except via the engagement floor constraint. Games are instruments, not rewards.

§ 6
Per-Game Behavioral Signals PHASE 2

The Ledger records (config_vector, outcome, signals) per session. The outcome (rank_pct) is game-agnostic. The signals are game-specific — they encode the behavioral fingerprint of how the student played, not just what they achieved. These signals are what make the posterior update more than a single rank_pct scalar. They feed the dimension-level evidence rather than the game-level Elo.

Constellation signals are already implemented (archetype_tag, strategy_shift_count, move_log, round_snapshots). The following are specified for future implementation.

§ 7
Cross-Game Transfer Model REQUIRES DATA

The transfer model answers the question: does dimension X measured in Game A predict dimension X in Game B? If yes, the dimensions are genuinely cross-game cognitive properties — not game skills. If no, what looks like "SIM" in GOLAD is GOLAD-specific pattern recognition, not a general simulation faculty.

The model cannot be specified in advance of data. What can be specified is the structure it will take and the evidence required to trust it.

Transfer Model Architecture
Input
→
Ledger records from M students × N games × T sessions each. outcome (rank_pct) and behavioral signals per session. Session config vectors used to label which dimensions were active at what difficulty.
Step 1
→
Per-student, per-game, per-dimension performance score derived from rank_pct weighted by the composition matrix loading for that (game, dimension) pair. Result: a (student × game × dimension) tensor of performance estimates.
Step 2
→
Factor analysis across games for each dimension. If SIM as measured by GOLAD correlates with SIM as measured by Constellation (r > 0.5) after controlling for general performance, the SIM dimension is confirmed as cross-game. If not, split into SIM_GOLAD and SIM_CONST as separate dimensions.
Step 3
→
Update composition matrix with empirical loading coefficients replacing the ASSERTED ordinal rankings. Now the two-level compiler has quantified E[KL] estimates rather than ordinal rankings.
Step 4
→
The game-level Elo is retired. The student model is now a (dimension × posterior_mean × posterior_variance) vector. The compiler operates in dimension space, not game space. Games are instruments; dimensions are the measurement targets.
Required
→
ASSERTED minimum: 30+ sessions per student across at least 3 games. 20+ students meeting this threshold. May require 6–12 months of operation before Step 2 becomes feasible. Until then, the ASSERTED composition matrix is the prior.

What if transfer fails? If no cross-game transfer is found — if every dimension is game-specific — then the universal cognitive space does not exist in the form asserted. This would mean each game measures a different thing entirely. The system would still work as a multi-game assessment battery (like separate subtests), but the two-level compiler's theoretical foundation changes: you select games to assess different domains, not to probe the same dimensions more efficiently. This is still valuable. It is not the architecture this document describes, but it is a valid fallback.

Partial transfer. The most likely outcome is partial transfer: some dimensions generalize (OPT, MOS) and others don't (KNW by definition). The practical implication is that the composition matrix will have some entries marked as cross-game (strong transfer) and others as game-specific (weak transfer). The compiler treats the former as true dimension probes and the latter as game-achievement measures tracked separately.

§ 8
Path to Objective Perfection

The system as described in this document is architecturally perfect. The One Principle applied to a universal cognitive space across a mechanically diverse game suite, with a two-level compiler and cross-game transfer model, is the correct structure. There is no better structure in theory.

The implementation is not perfect because the posterior is not yet faithful. The following table records exactly what needs to happen — not aspirationally, but as a precise list of replacements that will convert the current asserted system into an empirically grounded one.

The honest summary. The current system can measure cognitive development through Constellation with increasing precision as data accumulates. It cannot yet measure cross-game cognitive structure because (a) GOLAD, Geobridge, and C4D do not yet write to the Ledger, and (b) no student has played enough sessions across games for factor analysis to be feasible.

The immediate next step is not the two-level compiler. It is Ledger integration for all games. Every session in every game must be recorded with the same structure: config_vector (game-specific), outcome (rank_pct or equivalent), signals (game-specific behavioral fingerprint). Until then, the multi-game Ledger is empty and the transfer model has nothing to fit.

This document is the specification. The Ledger is the instrument. Time and sessions are the data. Objective perfection is not a state to be designed — it is a state to be measured into.
