The Four Permanence Axioms

1
Append-Only
Every measurement event is written once and never modified. A session ends — its Observation record is appended to the Ledger. The record's content is fixed at write time. No correction, no amendment, no deletion. If an observation was recorded incorrectly, a correction record is appended alongside the original. Both remain visible. The history is not sanitized.
Implementation: Ledger is a write-once log. Records carry a t (timestamp) that is the join key for all later interpretation. A "corrected" observation references the original's id in its supersedes field. Views can filter by latest-correction-wins; the raw log never does.
2
Non-Segmenting
The Ledger stores configurations as raw vectors — 12 continuous parameters. It does not store "mode: SPATIAL" or "template: FLOOD." Those labels are Layer 1 views applied to the config vector after the fact. A session with config_vector[1] = 500 is not a SPATIAL session — it is a session with dist_mult = 500. The label SPATIAL is one possible name for a region of config space. Naming the region does not create the region.
Implementation: Observation schema has config_vector: float[12] and config_hash: string. The mode_label field does not exist at Layer 0. Layer 1 views derive it as: mode = argmax(config_vector[0:4] / sum(config_vector[0:4])).
3
Retroactive Reinterpretation
When a better model arrives — a more accurate Elo algorithm, a new BT dimension mapping, a Phase 3 continuous skill surface — it is applied to the full Ledger history. All past observations are reinterpreted under the new model. This is possible only because the Ledger stores raw observations, not interpretations. A system that stores only the current interpretation of its data cannot retroactively correct its past.
Implementation: Every view is a query over the Ledger with explicit parameter versions. Changing params_version reruns the query with new weights. The scatter in Config Space re-renders under any projection. No data is frozen in interpreted form.
4
Full Provenance
Every Layer 1 value traces back to specific Layer 0 records. The confidence interval on a student's SPATIAL Elo is not a property of the number — it is a property of the set of records that produced it. When you see Elo = 720 ± 55, the ± 55 means: "here are the 4 sessions in config_vector[1] ≥ 300 that produced this estimate; their outcome variance is what generates the confidence band." Click any Layer 1 value. The Layer 0 records that produced it are shown.
Implementation: Layer 1 values carry a source_obs_ids: string[] field listing the Layer 0 record ids used in their derivation. Any uncertainty metric is derived from those records, not asserted independently.
