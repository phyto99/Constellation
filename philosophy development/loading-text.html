Constellation — Loading Text

Philosophy doc · Context, pools, generation rules · Era: background design, implement when loading states are built

What Loading Text Is

Loading text appears while the system fetches data, creates a room, connects players, or transitions between states. These are the moments when students have nothing to do but wait. They are short windows — 0.5s to 3s typically — but they are also moments of lowered resistance. The student is not actively doing anything, so the system can speak without interrupting.

Loading text is not instructional. It is not a progress bar with words. It is not a tip. It is the same voice as the terminal — brief, philosophically accurate, never explaining itself — dropped into a moment of ambient attention.

Loading text = terminal voice at ambient volume. Same register. Shorter. No context expected.

What Makes Loading Text Different from Terminal Voice

DimensionTerminal VoiceLoading Text
Length3–4 lines1–2 lines
ContextCompiler has zone, session count, signalSystem may have nothing — just an action in progress

ToneAddictive mysterious friendSame voice, reduced to essence
RepetitionCycling pools per zoneRandom pull — load events are random, not sequential
Self-referenceCan reference the session aheadNever reference what's loading — that breaks the spell

Context-Keyed Pools

Loading text is keyed to the action being performed, not the student's zone. Zone-specific loading text is possible later (Era 12+) but creates coupling complexity — the system needs zone data during the load event itself. Phase 1 uses action-keyed pools only.

WrongPlease wait while we connect you to the server

WrongFun tip: Try capturing the center territories first!
RightAdaptability starts before the round does.
Wrong"You're almost in! Just a few more seconds...
RightGive it a moment.

The anti-pattern in all bad examples is: explaining the wait. The system never explains the wait. It is ambient, not apologetic.

Implementation Notes

Never display the same loading text twice in one session. Randomise without replacement within the pool, then reshuffle. The student shouldn't notice the system repeating itself.

Loading text should appear after a 150ms delay — do not flash text for loads under 150ms. This prevents the text from appearing as visual noise on fast connections.

If a load takes over 3s, cycle to a second message. If it takes over 8s, switch to the reconnect pool regardless of original context — something is wrong and the voice should match that.

Text should disappear without fanfare — the transition into the loaded state is the signal that loading is done. No "Done!" or "Connected!" moments.

Era 12+ Extensions

Once zone data is available at load time, loading text can be keyed to zone × action. For example:

RADICAL · Joining
Something different was found for you.
Give it a moment to load.
ECHO · Session Start
Back in familiar territory.
Let's see what you do with it.
ALPHA · Compiler Thinking
The system is processing something it hasn't seen before.
This will take a moment.

These are Era 12+ because they require the compiler to return zone data before the load event completes — a sequencing challenge not worth solving in early builds. Seeds are written here for when that constraint lifts.
