System Architecture

Philosophical Axioms

The only objective ground truth in any competitive session is score rank among peers under identical configuration. All other signals — playstyle, behavior patterns, time-on-task — are mode-conditioned and only valid when the session mode was declared in advance and the player was attempting the declared challenge. "Better strategy" is undefined: any approach that achieves a higher rank is valid. Winning by 1 point is as valid as winning by 1000.
#AxiomImplication
①Zero-data valid startUniform priors. System works day one.
②Rank is the ground truthScore percentile vs peers, same session, same config.
③Signals are mode-conditionedsteal_rate in DESTRUCTION ≠ steal_rate in QUANTITY.
④Collaborative ≠ competitiveStaircase sessions use target-delta, not rank.
⑤Flow zone is optimalBarely winning (~top 30%) = maximum learning signal.
⑥Coverage before depthAll 6 modes explored before any mode repeats.
⑦Graceful degradationFewer sessions → fewer active features, not wrong ones.

Six Cognitive Modes

Epistemics note: These modes are session configurations, not player trait labels. A player who scores well in SPATIAL mode sessions is not "a spatial thinker" — they scored well under those constraints. Cognitive inferences beyond score rank require external validation (e.g., standardized brain training data). The mode system maximizes the variety of challenges seen, not the measurement of traits.

Player Profile

Mode Elo (000 = best · 999 = worst · lower = stronger · outer ring = lower elo)

* Mode Elo updates ONLY from competitive sessions where that mode was declared. A player with no SPATIAL sessions has no SPATIAL Elo — default 500, not inferred from playstyle.

Brain Metrics (optional — from external assessment)

* Brain metrics are supplementary only. They gate nothing on their own — they bias mode weighting when present and validated. Absent brain metrics → system functions identically, just without the bias.

Entropy Engine

Mode Coverage Simulation (Latin Hypercube)

Guarantee: every 6-session window contains each mode exactly once before any mode repeats. Within that constraint, underexplored modes and high-Elo modes are weighted higher.

Selection Weights

Weight Formula

w(mode) = coverage_weight × elo_weight
coverage_weight = 1 / (freq + 1)
elo_weight = (mode_elo / 999) ^ 0.7

Higher elo (worse) → higher weight
Less-seen mode → higher weight
Latin hypercube guarantee overrides weights

Multipliers (negatives allowed — drag)

Multiplier Shuffle — Bandit Problem

Admin Fisher-Yates shuffles which value maps to which dimension label. Players see "Stars Claimed / Distance / HQ / Destruction" but the reward structure is reshuffled. Players must deduce the new mapping from score feedback alone. This is the core epistemic challenge of INVERSION mode — heuristics from prior sessions become liabilities. Multipliers can be negative: the dimension that previously earned points now costs them.

Server (ConstellationRoom) independently validates all claims via validateClaim(), validateSteal(), validateHQ(). Score rank is computed server-side. Centauri is a real-time N-body gravity simulation with hex-grid territory control. Win condition = highest resource score at session end (sessionDuration). All physics is deterministic: clients sync from server startAt timestamp. Host-only: collision detection + planet position broadcast (every ~1s).

Move Pool Mechanics

team_move_pools[team_id] is global and never resets between rounds. use_team_move() decrements by 1, clamped at 0. distributeMoves() splits across players with random shuffle for remainder. A team that exhausts its pool cannot place cells — permanent constraint. This makes move allocation a strategic resource with compounding consequences.

Session Validity & Analytics Flags

Signal Validity Matrix

Which behavioral signals are analytically valid in each mode.
* A signal marked VALID means it is interpretable in that mode context. PARTIAL means it provides some information but with caveats. INVALID means it is too confounded by mode mechanics to draw conclusions.

Flow Zone — Target Calibration

Optimal learning = player wins by a small margin. From educational research (Vygotsky ZPD, Csikszentmihalyi flow): target zone = top 25–40% of session rank, not necessarily 1st. Crushing opponents = too easy → reduce challenge next session. Never winning = too hard → reduce challenge next session.
Simulated session rank percentile: 50%
0% (last) FLOW ZONE (25–75%) 100% (1st)
* "Barely winning" is the single most informative outcome. It confirms the challenge was appropriately calibrated AND that the player was genuinely engaged. Landslide wins and losses both reduce signal quality.

Collaborative Staircase Mode

In class sessions, all players are assigned different targets (e.g., P1 → 100 stars, P2 → 200 stars, P3 → 300 stars). Goal = hit your target, not beat others. Analytics = distance from target, not rank. No competitive Elo update. Records: target_hit_rate, overshoot_rate, target_approach_strategy.
Simulate staircase (4 players)
* Analytics in staircase mode: target_delta = (achieved − target). Positive = overshoot (easy). Negative = undershoot (too hard). target_hit_rate accumulates across staircase sessions. This feeds ONLY difficulty calibration, not mode-Elo or cognitive inference.

Team Composer

Composition Algorithm

Teams are not composed to maximize "winning" — they are composed to maximize the information gained from the session outcome. A session where one team crushes another gives minimal signal. A session where teams finish within 10% of each other gives maximal signal.
PriorityObjectiveMethod
1Elo balanceTeam mean Elo within ±10% of global mean
2Mode coverageCollective team set covers all 6 modes
3Cognitive diversityMinimize within-team cosine similarity of mode-Elo vectors
4Weakness exposureEach player faces their weakest mode context at least 1/6 sessions
5Bot fillBot archetype = argmax(missing mode affinity in team)
* Priority 1 is a hard constraint. Priorities 2–5 are soft objectives, optimized within the Elo balance constraint. If Elo balance and mode coverage conflict, Elo balance wins.

Two humans → 2+2 human+bot hybrid teams.
Bot archetypes chosen to fill missing cognitive modes in each team.
