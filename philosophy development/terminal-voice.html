Design Rules
What makes the voice work — and what breaks it
Rule 1
Speak about the session. Never about the student as a data point.
The terminal is not a report card. It speaks about the space the student is about to enter, not about who they are or what was measured.
✗ "Based on your last 12 sessions, you tend to underperform in..."
✓ "RADICAL. The system found a gap. This session goes after it."
Rule 2
Zone code words are used, never explained.
RADICAL, ECHO, CALIBRATION — these earn meaning through experience. The terminal uses them from session 5 onward without glossing them. A student who has played 20 sessions knows what RADICAL feels like. That knowledge is earned, not given.
✗ "You are in the RADICAL zone, which means you are in a stretch state."
✓ "RADICAL. This will feel different. That is the point."
Rule 3
The voice gets more specific as the system knows you. Never less.
Session 1 is deliberately open. "Embrace the chaos." Session 40 in SINGULARITY is precise and strange. The movement is always toward specificity, never toward generic. A message that could apply to anyone is a failure.
Rule 4
Short lines. White space. Never explain yourself.
The terminal is not a paragraph. Every message is 2–4 lines maximum. Blank lines are real content — they give the reader space to sit with what was said. The voice never justifies itself or explains why it said something.
Rule 5
The "addictive friend" quality: genuine, not performed warmth.
The friend quality comes from lines that feel true and slightly surprising — not from exclamation points or emoji. "You came back. That's usually how it starts." feels like a friend because it notices something real without making a big deal of it. Performed warmth ("Great to see you again!") is the opposite of this.
✗ "Welcome back! Ready for another great session?"
✓ "You came back. That's usually how it starts."
Rule 6 — ECHO specifically
ECHO must not feel like a consolation prize.
ECHO means consolidating familiar territory. Done wrong, this sounds like "you didn't grow enough for RADICAL." Done right, it sounds like being handed something real to work with. The energy is earned, not stuck. "You built something here. Now go deeper into it."
✗ "Familiar territory. Consolidating."
✓ "ECHO. You built something in this territory. Now find out how deep it goes."
Stage 1
First session only — the onboarding moment

Fires exactly once, the first time a student loads the panel. Never repeats. This is the friend leaning over before the game starts — conspiratorial, warm, slightly cryptic. Not a welcome screen. Not a tutorial prompt. An invitation.

Session 1 only · Never repeats
Looks like this is your first game. If you can adapt fast enough, you may win. Embrace the chaos.
index 0
only message
Why this exact message: It doesn't explain what the game is. It doesn't promise anything. It says "you might win" — not "you will win" — which is honest and slightly provocative. "Embrace the chaos" is a directive, not a description. It tells you how to approach what you're about to experience rather than explaining what that experience is. The warmth comes from the register: friend, not institution.

Stage 3 · Sessions 5+
Zone-specific voice — cycles within each zone pool

From session 5 onward the zone code word appears in the terminal. The zone name sits in the badge and in the first line of the message. Each zone has a pool of messages that cycles in order — so the student doesn't see the same thing every session, but nothing is random. Cycling rule: index = sessionCount % pool.length

CALIBRATION · Sessions 5+ with weak signal

Shouldn't persist past ~8 sessions. If it does, the student isn't playing often enough for the system to form a picture. The voice acknowledges this without guilt.

Host Mode
Social framing — replaces zone voice entirely when hosting

When a student switches to Host mode, the terminal switches register entirely. It's no longer personal — it's social. It speaks about the room and what's about to happen in it. Zone doesn't appear. Cycles through these regardless of session count.

Cycling Logic
How the system chooses which message to show

Messages cycle in order within each pool. The index is derived from sessionCount % pool.length — so a student always progresses through the pool sequentially, never sees the same message twice in a row (unless the pool has only one message), and the sequence resets gracefully.

Stage 2 messages (sessions 2–4) are position-fixed: session 2 → index 0, session 3 → index 1, session 4 → index 2. After session 4, the zone voice takes over regardless.

Example: student with 8 sessions in ECHO
Session 1Looks like this is your first game. If you can adapt fast enough, you may win. Embrace the chaos.
Session 2You came back. That's usually how it starts.
Session 3The chaos is designed. Most people feel it as a problem...
Session 4The system is still listening...
Session 5ECHO. You built something in this territory. Now find out how deep it goes. [idx 0]
Session 6ECHO. The system knows you here... [idx 1]
Session 7ECHO. Familiar ground isn't the same as easy ground... [idx 2]
Session 8ECHO. You built something in this territory... [idx 0 again]
Note for developers: If the zone changes between sessions (ECHO → RADICAL), the index resets to 0 for the new zone pool. Track lastZone in localStorage and compare to current zone on load — if different, reset the zone cycle index. This means a student who bounces between zones gets the opening message for each zone they haven't visited recently.
