The Principle
d* = argmaxd Ey[KL( P(θ | y, d, data) ‖ P(θ | data) )]
d = candidate session (mode × template). θ = student's true cognitive state. y = outcome we would observe. The selected session is the one that, in expectation, most changes what we believe about the student. Everything else in the system — zone, mode, template, difficulty, forgetting, velocity — is a consequence of this equation.
The Wrong Question

The current heuristic system asks: how do we combine elo, velocity, staleness, and engagement into a weight that ranks sessions? The answer is elo0.7 × 1/(τ+1) × vel_mod × hyp_mod × eng_mod. Every factor in that product is a parameter someone guessed. The system works in the same sense that a thermometer works — it reads the environment. But it does not model the environment.

The question was always wrong. The right question is: given everything we have recorded about this student, which session would most reduce our uncertainty about their cognitive state? That question has a precise mathematical answer. It requires no guessed exponents. It produces the zone, the mode, and the template as consequences, not as inputs.

The current architecture is already structured as Bayesian inference — it is simply doing it wrong. The ledger is the observation history. The state (elo, vel, tau) is a handmade approximation of the posterior. The weight formula is a handmade approximation of expected information gain. Zone selection is a handmade approximation of comparing d* to d_last. This document replaces the approximations with the thing they were approximating.

The State θ — Minimum Sufficient

The current state encodes three values per mode: position (elo), momentum (vel), recency (tau). The Bayesian state encodes three different values per mode: mean (μ), uncertainty (σ²), forgetting rate (λ). This is the same 18-dimensional minimum sufficient state identified in perfect-system.html — the dimensions are correct; only the semantics change.

HeuristicBayesianWhy it's better
elo[i] μ[i] Same concept. elo is a point estimate. μ is a posterior mean — same number, but now the system knows how confident it is in that number.
vel[i] (emergent) Velocity is ∂μ/∂t — the slope of the posterior mean over time. It is not stored separately; it falls out of the update equations. No vel_mod parameter needed.
tau[i] (drives σ² growth) Staleness is not a separate dimension. Time elapsed inflates σ²[i] via the forgetting model. The "staleness modifier" is a consequence of σ², not a separate factor.
— (missing) σ²[i] Posterior variance. How confident is the system about μ[i]? This is the dimension the heuristic system is missing entirely. It drives session selection: high σ² → system experiments more.
— (asserted: 1/14d) λ[i] Forgetting rate per mode, per student. Initially asserted (λ=1/30d prior). Learned from data in Phase 3. Replaces the single hardcoded 14-day half-life for the entire system.
The Model — Kalman Filter on Cognitive State

Between sessions, the student's cognitive state evolves. Skills regress slightly toward the prior (forgetting). Uncertainty about those skills grows (more time = less confident). This is an Ornstein-Uhlenbeck process. The Kalman filter gives the exact posterior update for this class of models.

Predict step — time elapsed τ days since last session on mode i
// Mean: regress toward prior (forgetting) μ_pred[i] = μ_∞ + exp(−λ[i] × τ) × (μ[i] − μ_∞) // μ_∞ = 500, the prior mean // Variance: grow toward stationary (uncertainty) σ²_pred[i] = σ²_∞ + exp(−2λ[i] × τ) × (σ²[i] − σ²_∞) // σ²_∞ = 5625 (75²)
Update step — outcome y observed after session on mode i
K = σ²_pred[i] / (σ²_pred[i] + R) // Kalman gain — how much to trust new evidence vs prior μ[i] ← μ_pred[i] + K × (y − μ_pred[i]) // posterior mean (moves toward observation) σ²[i] ← (1 − K) × σ²_pred[i] // posterior variance (always shrinks)

R is the observation noise for this session — how much of the outcome is skill vs noise. R decreases with template depth (more constrained template → cleaner signal) and increases with Q2 contamination (announced INVERSION inflates noise because the student's response is partially to the announcement, not to the mode). R is [ASSERTED] initially and becomes [LEARNED] in Phase 3 from the variance of residuals across sessions.

Velocity (∂μ/∂t) is not stored. It falls out: the difference between μ_pred (what we expected) and μ_updated (what we measured) is the velocity signal. The system doesn't need a separate vel[] array because the posterior carries this implicitly. The heuristic vel_mod > 12 penalty (elo moving too fast = unreliable) is now captured by the Kalman gain K — when outcomes vary wildly, K is already small, dampening the update.

Session Selection — argmax E[KL]

For a Gaussian likelihood model, the expected information gain of session d = (mode i, template t) has a closed form. No sampling required. The system evaluates all candidates analytically and picks the maximum.

Information gain for candidate session d = (mode i, template t)
I(d) = ½ log( 1 + σ²_pred[i] / R(t) ) // R(t) = R_base / depth(t) × purity_penalty(i) // depth(t) = locked axes count for template t (from TEMPLATE_DEPTH — same as heuristic) // purity_penalty(i) = 3.0 if mode i has Q2 contamination and no silent overlay, else 1.0 // R_base [ASSERTED] → [LEARNED] in Phase 3 from residual variance per template
The selected session
d* = argmax(i,t) I(i, t) // over all eligible (mode, template) pairs

This is why the formula is correct: I(d) is large when σ²_pred[i] is large (we know little about mode i, so observing it is informative) and when R(t) is small (the template gives a clean signal). Both are meaningful. A deeply familiar mode with low uncertainty produces low I(d) — the system already knows. A stale mode with growing uncertainty produces high I(d) — the system has forgotten and wants to know again.

The heuristic weight formula was approximating this: elo^0.7 ≈ σ²^0.5 (uncertainty grows with skill variance), 1/(τ+1) ≈ the R(t)/σ² ratio as τ grows, TEMPLATE_DEPTH is identical. The Bayesian formula is what the heuristic was reaching toward.

INV eligibility. The current heuristic has an explicit gate: τ[5] < 7 AND e[5] < 300 AND not cooldown. The Bayesian model has no gate. The purity penalty on announced INVERSION (R × 3.0) automatically deprioritizes INV when the signal is contaminated. Silent INVERSION (plannedSilentOverlay=true) removes the penalty: the system no longer needs the gate because R is now honest. Cooldown between INV sessions: σ²[5] drops sharply after an INV session (we just observed it). I(d) for INV falls below other modes naturally. No cooldown rule needed.

YOUNGER suppression. This remains an explicit rule (sessions < 20). It is not a statistical property — it is a design decision about developmental readiness. It stays.

Zone Vocabulary — Communication Layer from Posterior

In the heuristic system, zone is a selection input — it constrains what mode and template are chosen. In the Bayesian system, zone is a communication output — the session is selected first (argmax I(d)), and then the zone label is applied to describe the relationship between d* and d_last. The vocabulary survives intact. The computation underneath changes.

The zone labels are now exact rather than approximate. ECHO no longer means "probably the same territory" — it means the optimal session is identical to the last session. RADICAL no longer requires a rank threshold — it emerges when the argmax has jumped a large distance, which happens when σ² is concentrated in a non-adjacent mode.

What Gets Learned — Phase 3 Closure

Every [ASSERTED] parameter in the current system dissolves in Phase 3. They do not get replaced one by one — they dissolve entirely into quantities that the Bayesian model infers from data.

ParameterCurrent statusPhase 3: learned from
λ[i] — forgetting rate ASSERTED 1/30d Residual between predicted μ_pred (after τ days) and observed outcome y. High residual after short absence → fast forgetter (high λ). Learned per mode, per student.
R(t) — observation noise ASSERTED R_base/depth Variance of (y − μ_pred) across all sessions on template t. Low variance → clean template → low R. Learned per template across the entire cohort.
σ²_∞ — stationary variance ASSERTED 5625 Long-run variance of outcomes per mode. Converges from cohort data after ~100 sessions per mode.
μ_∞ — prior mean ASSERTED 500 Population mean elo across all students at session 1. Directly measurable. Updates continuously.
purity penalty — R multiplier ASSERTED 3.0 Compare I(d) predictions vs actual information gain on contaminated vs clean INV sessions. The ratio IS the penalty. Learned from silent vs announced INVERSION comparison (Phase 0 + Phase 3).

After Phase 3, the only remaining [ASSERTED] element is the choice of model family (Gaussian likelihood, Ornstein-Uhlenbeck forgetting). That choice will survive because it is falsifiable: if the residuals are non-Gaussian, we will see it in the evidence feed. A non-Gaussian residual structure is the pre-registered refutation condition for the model family itself.

What Stays — Invariants
The Ledger
Append-only raw observations. The Bayesian model reads observations from the ledger and writes posterior updates. The ledger is unchanged — it is the observation history, not the model.
Zone Vocabulary
ECHO · PARALLEL · SHIFTING · RADICAL · REMATCH. The labels survive. Students have already learned them. The computation underneath changes from threshold rules to posterior comparison.
Mode Framework
6 cognitive modes (QTY, SPT, FRT, DST, WRM, INV). The mode framework is a design decision about what cognitive dimensions to measure, not a statistical choice. It stays.
3-Layer Terminal
Layer 1 disclosed, Layer 2 named, Layer 3 hidden. The information architecture is unchanged. The terminal still shows zone, mode, template. The math is still never shown.
Codename System
The canonical codenames (challenge-meta.html) are community vocabulary. They are indexed by session count, unchanged. The Bayesian model does not affect the naming layer.
MODE_ADJACENCY
The adjacency map (QTY↔SPT, SPT↔FRT↔WRM, FRT↔DST, DST↔INV, INV↔WRM) is a cognitive design decision — which modes share underlying structure. It stays and is used in zone classification.
Q2 Semantics
Announced INVERSION = contaminated signal. This is not a statistical claim — it is a measurement design constraint. Silent INVERSION removes the purity penalty. The Q2 frame survives unchanged.
Evidence Axiom
Record observations, not interpretations. The Bayesian model produces interpretations (posteriors). The ledger records only what happened. The distinction is preserved — and now more important than ever.
Build Order — Migration Path

The Bayesian compiler does not replace the heuristic compiler at once. The migration is additive — the Bayesian model runs alongside the heuristic, both producing outputs, both feeding the ledger. Phase 3 is when the heuristic is retired.

Phase −1
Start the ledger. The Bayesian model is useless without observations. Every session not recorded is an observation permanently lost.
URGENT
Phase 0
Silent INVERSION (clean purity signal), elo_velocity tracking (needed for residual estimation), template history, forgetting measurement (τ per mode). These are the observations the Bayesian model will train on.
NEXT
Phase 1
Run Bayesian compiler in shadow mode — compute d* alongside heuristic, log both, compare. Do not switch sessions yet. Measure divergence between heuristic and Bayesian selections.
AFTER LEDGER
Phase 2
Switch to Bayesian selection for RADICAL and SHIFTING zones first (highest divergence from heuristic, highest expected gain from getting it right). Keep heuristic for ECHO/PARALLEL/REMATCH (lower stakes, smaller divergence).
AFTER SHADOW
Phase 3
Learn λ[i], R(t), σ²_∞ from accumulated data. Replace all [ASSERTED] parameters. Retire heuristic compiler. All [ASSERTED] labels become [MEASURED]. System is now fully self-calibrating.
